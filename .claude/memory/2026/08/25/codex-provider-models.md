# Codex + DeepSeek: provider selection, models.json, and the /v1/models gap

Recorded 2026-08-25 after making `cods` work end-to-end. Captures the single-source
provider-model design and preserves the key facts from the rule files that were moved
out of `.claude/rules/rem/` (see "Preserved rules" below).

## Single source of truth: `providers.<name>.models`

`claude_env_settings.json` is the one source. Each provider declares `models` once
(base = canonical; optional fable/opus/sonnet/haiku/subagent per-class; `codex` override):

```json
"deepseek": {
  "url": "https://api.deepseek.com", "claudeApiKeyEnv": "ANTHROPIC_API_KEY",
  "claudePath": "/anthropic", "codexApiKeyEnv": "DEEPSEEK_API_KEY", "codexPath": "/v1",
  "models": { "base": "deepseek-v4-flash[1m]", "fable": "deepseek-v4-pro[1m]",
              "opus": "deepseek-v4-flash-vision-exp[1m]" }
}
```

Both launchers derive their projection from `models` (no `claudeModel`/`codexModel`/
`claudeExtras` drift). `[1m]` is a Claude-side context-window suffix; codex uses the bare id.
Full schema: `docs/providers.md`.

## Codex launcher: MUST select the provider (`--config model_provider=<name>`)

`codex-launcher.mjs` sets `env[codexApiKeyEnv]=apiKey`, `--config model_provider=<name>`,
`--model <codexModel>`. Do NOT override `--config openai_base_url=...` — that runs codex as
the **openai** provider (chatgpt auth from `~/.codex/auth.json` → 401 against deepseek, and
the openai model list in the picker). `model_provider=deepseek` resolves the
`[model_providers.deepseek]` block in `codex_config.toml` (base_url + env_key + wire_api),
which uses DEEPSEEK_API_KEY and wire_api=responses. The DeepSeek setup script deletes any
global `openai_base_url` for the same reason.

## models.json full schema (required by Codex)

Codex 0.149 rejects a minimal models.json (falls back to its bundled OpenAI list). A
schema-complete entry must include (mirrored from DeepSeek's setup script):
`prefer_websockets, support_verbosity, default_verbosity, apply_patch_tool_type,
web_search_tool_type, input_modalities, supports_image_detail_original, truncation_policy,
supports_parallel_tool_calls, tool_mode, multi_agent_version, use_responses_lite,
include_skills_usage_instructions, auto_review_model_override, context_window,
max_context_window, effective_context_window_percent, auto_compact_token_limit, comp_hash,
reasoning_summary_format, default_reasoning_summary, display_name, description,
default_reasoning_level, supported_reasoning_levels, shell_type, visibility,
minimal_client_version, supported_in_api, availability_nux, upgrade, priority,
model_messages, experimental_supported_tools, supports_search_tool, default_service_tier,
supports_reasoning_summaries, base_instructions`.

Codex 0.149 REQUIRES every entry to have `base_instructions` (or
`model_messages.instructions_template`) — a models.json without it is REJECTED
("missing both base_instructions and model_messages.instructions_template") and the picker
falls back to the built-in openai list. The generator sets `base_instructions` to the repo's
OWN `system-prompt/codex-base.md` (single source, NOT DeepSeek's embedded "You are Codex,
based on GPT-5" prompt), so the prompt stays the repo's. The catalog is written to repo
`models.json` and linked to `~/.codex/models.json` (CODEX_LINKS), regenerated by setup.

## Picker fix: `model_catalog_json` config

Codex 0.149 does NOT auto-read `~/.codex/models.json` for the picker — the models manager
tries the provider's `/v1/models` and, on DeepSeek's OpenAI-compat format
(`{"object":"list","data":[...]}` vs codex's expected `models` field), falls back to the
bundled openai list. The fix is to point codex at the catalog explicitly in config.toml:

```toml
model_catalog_json = "~/.codex/models.json"
```

`inject-codex-providers.mjs` `generateModelProvidersBlock()` emits this into the
setup-managed section, so setup wires it automatically. With it + a schema-complete
`models.json` (incl. `base_instructions`), codex uses the catalog for the picker list and
metadata, and the deepseek models show in `--model`. Verified end-to-end: `codex exec
--config model_provider=deepseek --model deepseek-v4-pro` returns a response with no
`/v1/models` decode error and no "metadata not found". `gmi` also needs its apiKey in the
machine-local file for `cogmi`.

## Operational: `~/.codex/config.toml` must stay linked to the repo

The repo's `codex_config.toml` (with the generated `model_providers.*` + `model_catalog_json`)
is the single source; setup links it to `~/.codex/config.toml`. If the link goes stale (a
separate file copy), repo config edits stop reaching codex — re-run `npm run setup`.

## Preserved rules (moved out of `.claude/rules/rem/` 2026-08-25)

These were reference material, not always-injected rules, so they left `rules/` — their
knowledge is preserved here and in `docs/providers.md`.

- **Windows `windowsHide: true`** (was `no-terminal-flash.md`): every spawn/spawnSync/
  execFileSync/execSync that launches a console app from a hook or background script
  (`git`, `node`, `powershell`, `claude`, ...) MUST pass `windowsHide: true`, or a console
  window flashes on Windows. Never wrap in `cmd /c start` unless the child must outlive the
  hook (then use `start "" /B` + `windowsHide` + `-WindowStyle Hidden`). Foreground launchers
  the user invokes in their own terminal with `stdio:'inherit'` don't flash.
- **Hook pending-work guard** (was `hook.md`): `rem-hook.js` skips advancing Stop-hook
  state when `hasPendingWork = background_tasks.length > 0 || now < taskActiveUntil`, so it
  can't interrupt sharp-review/fabric/codex workflows. Multi-round skills that run in a single
  turn without background tasks MUST set `taskActiveUntil` (30-min auto-expire), or the Stop
  hook may fire mid-skill.
